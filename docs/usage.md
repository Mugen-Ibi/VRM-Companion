# 使い方と復旧

## VRMを表示する

「アバター」→「VRMをインポート」でローカルファイルを選び、作者・利用条件を確認します。原本は変更せず、保存先へコピーします。描画に成功したモデルだけを選択状態として保存し、失敗時は理由を表示して直前のモデルを維持します。素材の入手や外見の選定は利用者に委ねます。

対応はVRM 0.x/1.0、100MiB以下、20万三角形以下、画像1枚4096px以下・展開合計256MiB以下、1万ノード以下です。外部参照、URI画像、圧縮メッシュは初期版で扱いません。表情がないモデルでも基本表示・会話・整理は使えます。

会話パネル右上の「アバターを隠す」で表示だけを止められます。「アバターを表示」で再開し、会話や整理の処理中も切り替えられます。アバターの右クリックメニューからも隠せます。非表示状態は次回起動にも引き継ぎ、モデルの選択や会話は保持します。アプリを終了する必要はありません。

モデルを左ドラッグすると移動し、左クリックすると会話パネルが開きます。透明部分はクリックを透過します。トレイの「移動モード」はウィンドウ全体で入力を受け取り、「全体クリック透過」はモデルの上も透過します。全体透過中はアバターの右クリックも背面へ通るため、会話パネルかトレイから操作してください。操作を戻す場合は「自動クリック透過」を選びます。設定で倍率・最前面・fpsを変更でき、非表示時は描画を停止します。

パネルの×は非表示です。終了はトレイの「終了」を使います。外部起動したllama-serverは終了しません。

「設定」のモーションは「おだやか」「にぎやか」「オフ」から選べます。呼吸・視線・まばたきに加え、手振り・うなずき・おじぎ・伸びを自動で行います。「アバター」画面または右クリックから個別の動作も指定できます。モデルの体格や衣装によって見え方は異なります。描画品質は省リソースが既定で、高画質ほど高DPI環境の描画ピクセル数が増えます。

## 会話と接続

アプリからLLMを選ぶ場合は、次の順で設定します。

1. 「設定」→LLMの使い方を「フォルダーから選択」にします。
2. 「GGUFフォルダーを選択」でモデルの配置先、「llama-server.exeを選択」で展開済みのllama.cpp実行ファイルを指定します。管理スクリプトの既定配置は `%LOCALAPPDATA%\VRM-Companion-LLM\models` と `%LOCALAPPDATA%\VRM-Companion-LLM\llama\llama-server.exe` です。公式配布物として確認できない実行ファイルは、SHA-256を表示して明示確認を求めます。
3. 「設定を保存」後、会話上部の一覧からモデルを選びます。選択時に読み込み、前のモデルは終了してから切り替えます。会話履歴は維持します。
4. 「メモリ解放」でLLMを終了できます。未使用時の自動解放は既定5分、0分で無効です。次の送信時に選択済みモデルを読み直します。読み込み中も「停止」できます。

検索は指定フォルダーの直下のみです。分割GGUFは全パートを同じフォルダーに置きます。画像用mmproj・不完全な分割・不正なGGUFヘッダー・シンボリックリンクは一覧から除外します。ファイルの追加後は「再読込」を押してください。会話テンプレートや構造化出力に対応しないモデルは、起動や意図判定が失敗する場合があります。

管理モードは自動GPU割当・1並列・短いコンテキストを用いて負荷を抑えます。まず4,096と小さいGGUFから始めてください。コンテキストの変更はLLMを解放し、次の利用時に反映します。モデルの重み自体に必要なメモリは削減できません。外部サーバーを同時に起動すると、その分のメモリも必要です。管理モードが終了するのは自分で起動した子プロセスだけです。

外部起動のLLMを使う場合は「起動済みサーバーに接続」を選びます。以下の接続先・キーはこのモードに適用します。

接続先は `http://127.0.0.1:ポート` または `http://[::1]:ポート` です。モデルIDは空欄で接続確認すると取得します。必要ならAPIキーを入力します。キーはWindowsアカウントに結びつくElectron safeStorageで保存します。

コンテキスト上限はサーバーの1スロットあたりのcontext以下に設定してください。`-c 4096 -np 1` なら4096です。応答上限は初期512tokensです。対応モデルでは思考出力を無効にして本文を表示します。会話テンプレート適用後のトークン数を計数し、必要なら古い会話をターン単位で省略して通知します。旧サーバーが計数APIに未対応の場合は保守的な推定に戻します。

名前・利用者の呼び名・口調を保存すると次の会話に反映します。生成中も「停止」できます。失敗した発言の「前の入力を再入力」は入力欄に戻す操作です。確認して送信してください。上限や通信断で途切れた本文は、不完全な応答として残します。

サーバー未起動、モデル準備中、APIキー不一致、タイムアウトをエラー表示します。LLMに接続できなくてもアバターや設定は使えます。通常会話にファイル実行能力はなく、結果はアプリの記録カードで確認します。

入力欄は「会話」が初期選択です。このモードは意図判定を挟まず応答し、整理を頼む文章でもファイル操作や整理案の作成を始めません。ファイル整理を頼むときは「整理依頼」に切り替えてください。新規会話・別の会話への切替時は「会話」に戻ります。

長い会話は直近100メッセージから表示し、「以前のメッセージを表示」で100件ずつ追加できます。表示を省略しても保存済み履歴は消えません。

## フォルダ整理と復元

1. 「フォルダを選択」で通常のローカルNTFSフォルダを明示選択します。
2. 入力欄の「整理依頼」を選んで「このフォルダを種類別に整理して」と送信するか、「種類別の整理案を作成」を押します。
3. 一覧の分類先を確認・変更します。「変更なし」で対象から外せます。
4. 「内容を検証する」でID・更新日時・サイズ・SHA-256を確認します。同名の移動先がある項目は除外して表示します。
5. 全移動元・移動先を確認して「この内容で整理する」を押します。10分経過、編集・再起動・権限変更後は再検証が必要です。
6. 成功した移動を戻す場合は「復元案を確認」→「この内容で戻す」を押します。変更済みや元パスが埋まっている項目は保持します。

対象は直下の通常ファイルだけです。固定カテゴリは画像・文書・動画・音声・圧縮ファイル・その他・変更なし。「その他」は手動のみ、未知の拡張子は変更なしです。分類にファイル名や本文をLLMへ送信しません。整合性検証のため内容をローカルでハッシュ計算します。

上限は走査1万エントリ、1計画200ファイル・2GiB、1ファイル512MiBです。サブフォルダの中へは降りません。リンク・隠し・システム・既知のクラウド属性、ネットワーク共有、システムやアプリの保存先は対象外です。同期ソフトの検出は網羅的ではないため、同期対象外を選んでください。

作業記録は1ページ10計画で、「以前の記録」「新しい記録」で切り替えられます。記録は自動削除しません。

停止は進行中の1操作を記録してから後続を止めます。完了済みを自動で巻き戻しません。新規作成した分類フォルダは復元後も残します。

## 作業の照合が必要なとき

クラッシュや操作失敗の後は「状態を照合する」を押します。元・先を記録と比較し、同じ操作を再実行せず結果を確認します。許可解除済みならフォルダを再選択してください。

外部変更等により成否を確定できない場合は、一覧の元・先をエクスプローラーで確認します。「実ファイルを手動確認して照合を終了」は、専用ダイアログで確認した計画だけを手動確認済みとします。ファイルは変更せず、成否未確定の記録を保持し、その項目を復元対象から外します。

記録の保存に失敗した間は新しい変更を禁止します。空き容量やアクセス権を直してから「状態を照合する」を再実行してください。手動確認だけでは記録障害の停止状態を解除しません。

## 保存とバックアップ

保存先の絶対パスは設定画面に表示します。通常は `%APPDATA%/vrm-companion` です。

| 内容 | 相対位置 |
| --- | --- |
| 設定・会話・許可・計画・操作記録 | `companion.sqlite`（使用中は `-wal` / `-shm` も存在） |
| 管理用VRMコピー | `avatars/<UUID>.vrm` |
| 明示作成したDBバックアップ | `backups/backup-<日時>-<UUID>.sqlite` |
| 破損復旧で保管した元DB | `damaged-<日時>-<UUID>/` |

設定・会話・許可・計画・操作記録は、ランダムなデータ鍵でレコードごとに暗号化します。データ鍵はWindowsの現在のアカウントで保護するため、DBやバックアップだけを別PC・別アカウントへコピーしても復号できません。初回更新時には既存DBとアプリ管理下のバックアップを同じ場所で暗号化移行します。

「バックアップを作成」は暗号化された一貫したSQLiteスナップショットを作ります。VRM本体は含まないため、同じWindowsアカウント内での復旧用として保存してください。別PCへの移行は、将来の専用エクスポート機能が提供されるまで未対応です。APIキーも移行先で再入力が必要です。バックアップは手動作成です。作成中もアバター表示の切替を使えます。バックアップと履歴削除は、開始後の処理が収束するまで終了を待ちます。

会話と作業記録の自動削除は行いません。

会話保存を無効にすると、その後の会話更新はメモリだけに保持します。既存履歴は個別削除か全履歴削除で消せます。通常のバックアップにも会話削除を反映します。復旧用の `damaged-` と利用者が外部へコピーしたバックアップは原本保管のため残ります。必要なら保存先から別途管理してください。ファイル操作の記録は会話保存と独立し、必ず保存します。

DB破損で起動できない場合は、案内から保存先を開くか、バックアップを選んで復元できます。元DBは別フォルダに保管し、フォルダの許可と承認を失効させます。バックアップ時点で未確定の作業を再照合し、確定済み記録は保持します。保存後に増えた会話や作業記録は戻らないため、整理対象の実ファイルも確認してください。正常なバックアップがない場合は原本を保持して調査します。

アンインストールは終了後に配布フォルダを削除します。原本VRM・GGUF・整理対象・保存データは別の場所にあり、自動削除しません。
## 入力操作の修正（v0.0.0.4）

状態更新中も入力欄と編集履歴を維持します。Enterで送信、Shift+Enterで改行し、日本語変換中のEnterは送信しません。エラー通知は画面上部に表示され、長い内容は通知内でスクロールできます。


## 失敗時・停止時の動作（v0.0.0.5）

送信は受理された履歴を確認してから入力欄を消します。受理前のエラーでは下書きを保持し、待機中に編集した次の下書きも消しません。停止・失敗した会話ターンは次回のLLM文脈から除外しますが、画面の履歴と再入力ボタンは残します。APIキー保存後はキー入力と削除チェックをリセットします。保存待ち中に入力した別のキーは保持します。

フォルダ登録の停止では許可・選択の確定を中断します。会話削除中に停止すると、実行中のバックアップ処理が終了してから中断を確認し、メインDBの会話は削除しません。ただし、既にバックアップ内で削除済みの履歴は戻りません。完了済み処理を巻き戻す機能ではありません。
