# VRM Companion v0.0.0.3 Beta

Windows x64向けのベータ版です。v0.0.0.2から、状態管理の信頼性と履歴増加時の応答性を改善しました。

## 変更

- **会話と整理依頼を明示選択**：入力欄の初期値は「会話」です。意図判定を挟まず応答するため、通常会話に構造化出力は不要です。ファイル整理を頼むときは「整理依頼」を選びます。「整理案を作る」ボタンも従来どおり使えます。移動前の明示承認は維持しています。
- **設定保存の競合を修正**：LLM停止待ち中にアバターを隠したり別モデルを選んだりしても、その変更を古い設定で上書きしません。設定とAPIキー、アバター登録と選択はまとめて保存します。
- **状態通知を小さく**：全履歴・全計画の毎回送信をやめ、状態・会話・計画を個別に通知します。通知欠落を連番で検出し、全状態から再同期します。表示通知の失敗だけでファイル操作を失敗扱いにしません。
- **重い処理を分離**：DBバックアップ、過去バックアップ内の会話削除、VRM検査をworkerで実行します。埋込み画像は展開前にヘッダーから寸法を検査します。
- **履歴は保持**：会話は直近100メッセージから追加表示、作業記録は10計画ずつ表示します。会話・作業記録の自動削除は導入していません。
- **保存データを検証**：型付きRepositoryを導入し、起動とバックアップ復元前にレコードの形式を確認します。不正なデータは原本を保持して復旧を案内します。既存の正常な保存形式は引き続き使用できます。

## 起動・移行

1. 旧版をトレイの「終了」で閉じます。必要に応じて設定からバックアップを作成してください。
2. `VRM-Companion-0.0.0.3-win32-x64.zip`を新しいフォルダーへ展開し、`VRM-Companion.exe`を起動します。EXEだけを移動しないでください。
3. 同じWindowsアカウントの通常起動では既存の設定・VRM登録・履歴を引き継ぎます。
4. ファイル整理を文章で頼むときは、入力欄の「整理依頼」に切り替えてください。「会話」の文章から整理案は作りません。

VRM・GGUF・llama-serverは同梱しません。Node.jsとUnityは実行時に不要です。添付の`SHA256SUMS.txt`でZIPを確認できます。

## 検証・制約

負荷用の80会話・8,000メッセージ・100計画・20,000候補で、表示切替の状態イベントは約12.7MBから約942バイトに減少しました。操作時間は旧ビルド約147〜175ms、新ビルド約20〜29msでした。単一PC・各5回の合成負荷であり、物理入力から描画までの遅延や一般的な性能保証ではありません。

型検査・書式検査成功。自動テスト112件中111成功・既存環境条件のスキップ1件。実UIによる会話／整理依頼の分岐・移動・復元・VRM 0.x/1.0、新配布EXEの再起動・バックアップ・履歴削除、旧版のテストデータ引継ぎを確認しました。最終結果と配布物の検証記録は[検証記録](verification.md)を参照してください。

起動時の全履歴取得、全状態再同期、通常の同期DB読書きは残っています。巨大な履歴での起動時間・メモリ使用は今後の改善対象です。LLMを除く1GB目標、2時間連続表示、混在DPI・複数画面の受け入れ完了は今回も宣言しません。音声、コード署名、インストーラー、自動更新は含みません。
