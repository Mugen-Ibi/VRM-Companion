# VRM-Companion 要件定義書

作成・更新日: 2026-09-19 / 状態: 承認済み要件・実装後の受け入れ検証中 / 対象: 個人利用の初期版 v0.1（MVP）

本書は利用者が承認した要件を維持する。実装・テストの存在だけでは受け入れ完了とせず、要件ごとの最新結果、測定条件、未実施項目は[検証記録](verification.md)を参照する。

## 1. 目的と採用ゴール

**ユーザーが用意した任意のVRMアバターがデスクトップに常駐し、日本語のテキスト会話から、指定フォルダ直下のファイルを種類別に整理・復元できる。会話と作業はローカルで完結する。**

モデルの探索・選定・入手はユーザー個人に委ねる。メイドなど特定の外見・性別・衣装・人格や、「かわいさ」の評価はアプリの受け入れ条件にしない。「任意のVRM」は固定モデルや許可リストに限定しないという意味であり、対応仕様・リソース上限に適合するファイルを対象とする。破損や非対応のファイルには理由を表示する。

元の「Desktop Mate的な表示 + VRMインポート + llama.cppチャット／エージェント」という方向を採用する。そのうえで、完成の判断基準を機能の列挙から「毎日使える会話相手兼お手伝い役」という体験に置く。Desktop Mateは体験上の参考とし、同製品の全機能や素材の再現は目標にしない。

初期版の完成状態は、好みのVRMを読み込み、会話し、「このフォルダを整理して」という依頼から整理案の確認・実行・必要時の復元まで完結できること。音声と高度な自律行動は、この一連の体験を検証した後に追加する。

## 3. 中心となる利用シナリオ

### UC-01: 初回セットアップ

1. ユーザー自身でVRMを入手する。アプリを起動し、ローカルのVRMを選ぶ。未選択時はインポート案内を表示する。
2. モデルのプレビューと作者・利用条件などの埋め込み情報を確認する。
3. キャラクター名、利用者の呼び方、話し方を設定する。
4. 起動済みllama-serverの接続先を設定し、接続と短い日本語応答を確認する。
5. キャラクターの位置・大きさを調整し、チャットを開始する。

接続できなくてもアバターの表示と設定は利用できる。LLMモデルの自動選定・ダウンロードは初期版に含めない。

### UC-02: 日常会話

アバターまたはトレイから会話パネルを開く。入力すると待機から思考中の表情に変わり、日本語の返答が逐次表示される。送信取り消し、会話の新規作成、履歴削除ができる。応答中に別のアプリへフォーカスを移しても作業を妨げない。

### UC-03: フォルダ整理

1. 「ダウンロードを種類別に整理して」と依頼する。
2. 対象未設定なら、フォルダ選択画面で利用者が対象を指定する。自然文だけではアクセス権を追加しない。
3. LLMが依頼を解釈し、アプリが直下の通常ファイルを拡張子の固定ルールで分類する。例: `photo.png → 画像/photo.png`。未対応の整理方法は説明し、種類別整理への変更を選んでもらう。
4. 検証用ハッシュの計算進捗を表示し、移動前後のパス、件数、ルールに基づく分類理由、対象外を表示する。利用者は除外・固定カテゴリへの変更・キャンセルができる。
5. 「この内容で整理する」で表示した計画全体を一括承認する。
6. 実行結果を「成功・失敗・未実行」に分けて提示する。成功の根拠は実行記録とする。
7. 「元に戻す」で復元案を確認し、競合のない項目を戻せる。

毎ファイルの確認は求めない。計画が変わったときだけ承認し直す。日常会話の「はい」を実行承認として解釈しない。

## 4. スコープ

| v0.1の必須範囲 | 後続版で検討 | 初期版の対象外 |
| --- | --- | --- |
| VRM 1.0 / 0.xの基本表示 | 音声入力・読み上げ・リップシンク | 万能なGUI自動操作 |
| 透明常駐、位置・大きさ変更 | ウィンドウ上に座る、歩行、接触演出 | 常時画面監視、キーロガー |
| 日本語テキスト会話 | 明示的な長期記憶、検索拡張 | 管理者権限によるOS設定変更 |
| 表情、まばたき、軽い待機動作 | 複数キャラクター、追加モーション | 任意コマンド・生成コードの実行 |
| 直下ファイルの固定分類・承認・移動・復元 | 再帰整理、意味に基づく分類、定型作業の自動実行 | ファイルの削除・上書き・内容書き換え |
| ローカル履歴、設定、作業記録 | llama-serverのアプリ内起動管理 | クラウドLLM、ネット検索、外部送信 |

ファイル整理は、利用者が明示選択したローカルNTFSフォルダ直下の通常ファイルを、同じルート直下の固定分類フォルダへ移動する。サブフォルダは走査しない。初期版ではディレクトリそのものの移動、分類先フォルダ名の自由編集、ネットワーク共有、同期フォルダ、再解析ポイント経由の処理、使用中ファイルの強制操作を扱わない。承認・上書き禁止・実行記録・復元はMVPにも含める。

## 5. 機能要件と受け入れ条件

| ID | 要件 | v0.1の受け入れ条件 |
| --- | --- | --- |
| AV-01 | 任意VRMのインポートと選択 | 対応仕様・上限内のユーザー提供VRM 0.x / 1.0を読み込める。特定モデルに依存せず、各世代の検証モデルを表示できる。失敗時は理由を表示し直前のモデルを維持 |
| AV-02 | モデル管理 | 原本を変更せず管理領域へコピーする。作者・利用条件情報を表示し、削除・切替・再起動後の選択復元ができる |
| AV-03 | 常駐表示 | 透明背景、最前面の切替、移動、倍率変更、トレイからの非表示・復帰・終了ができる |
| AV-04 | 操作の邪魔をしない | キャラクター周辺の透明部分で背後のアプリを操作できる。全体クリック透過モードからトレイで復帰できる |
| AV-05 | モデルに応じた表示 | 利用可能な表情・ボーンでまばたき・待機動作を行う。表情不足でも会話と整理が動作し、思考中・返答・作業完了はパネルでも区別できる |
| CH-01 | ローカルチャット | llama-serverへ接続し、日本語のストリーミング応答・中断・再試行・エラー表示ができる |
| CH-02 | 人格設定 | 名前、口調、利用者の呼び方を保存し会話に反映。人格設定でPC操作の権限は変化しない |
| CH-03 | 文脈と履歴 | 会話単位で履歴を保存し、文脈上限を超えない。新規会話、個別会話削除、全履歴削除が可能 |
| CH-04 | 接続障害への対応 | サーバー未起動・モデル未準備・タイムアウトを区別し、表示や設定UIを停止させない |
| CH-05 | 会話から整理への接続 | 通常会話・整理依頼・確認待ち・未対応依頼を分岐し、選択済みrootIdを引き継ぐ。対象不明時は選択を求め、承認前にファイルを変更しない |
| AG-01 | 対象範囲の指定 | OSのフォルダ選択で許可ルートを登録・解除できる。外部パスを指定するLLM出力を拒否 |
| AG-02 | 整理案作成 | 直下ファイルを固定の拡張子ルールで分類する。同じ一覧とルール版から同じ案になる。未知の拡張子は変更せず理由を表示する |
| AG-03 | プレビューと承認 | すべての移動元・先を確認でき、除外・分類先修正後に再検証。明示ボタンでその計画だけ承認 |
| AG-04 | 検証付き実行 | 承認内容以外を実行せず、上書き・ルート外移動・任意シェルを拒否。進行状況と停止ボタンを表示 |
| AG-05 | 競合と中断 | 同名、ロック、対象変更を検出したら停止し、完了済みと未実行を区別。停止後に新たな移動を始めない |
| AG-06 | 復元と再起動復旧 | 成功した移動から復元案を作れる。クラッシュ後に未確定操作を照合し、二重実行せず復旧画面へ移る |
| AG-07 | 正確な完了報告 | 件数・パス・成否は実行記録からアプリが生成してチャットと結果カードに表示する。LLMの自由生成文を作業完了報告に使わない |
| AG-08 | 整合性検証の処理量 | 1ファイル512MiB・1計画合計2GiB・200ファイルを初期上限とし、超過時は対象を絞る。ハッシュ計算の進捗・中断・失敗を表示し、不完全な検証で承認可能にしない |
| ST-01 | 設定とローカル保存 | 設定、履歴、モデル、作業記録の保存場所を表示。再起動で復元。破損時はバックアップ／復旧導線を表示 |
| ST-02 | 常駐の管理 | 起動時常駐は初期状態で無効。終了操作でアプリ所有プロセスが終了し、外部起動のLLMは停止しない |

## 6. 非機能要件

| ID | 要件 | 評価方法／初期目標 |
| --- | --- | --- |
| NF-01 | ローカル完結 | セットアップ後、ネットワークを切断して会話・表示・整理が動く。外向き通信、テレメトリ、自動ダウンロードは既定で行わない |
| NF-02 | 描画 | 検証用VRM 1体で通常30fpsを目標。非表示時は描画停止。LLM負荷時は描画品質・fpsを下げられる |
| NF-03 | 応答性 | 推論中も入力・停止・ウィンドウ操作のUI応答p95を200ms以内にする。計測条件は開発計画で固定 |
| NF-04 | 推論速度 | 初回トークンまで5秒以内、生成15 token/s以上を暫定の快適性目標とする。PCとモデル決定後に調整し、CPUのみでの保証値にはしない |
| NF-05 | リソース | LLMを除くアプリ全プロセスのメモリ合計1GB以内を仮目標。GPU負荷・VRAM・待機CPU使用率も記録して常用可能性を評価 |
| NF-06 | データ保全 | 未承認変更・上書き・許可外変更は検証ケースで0件。復元競合時は現存ファイルを保持して報告 |
| NF-07 | 長時間利用 | 2時間の表示・会話・モデル切替でクラッシュせず、継続的なメモリ増加がない |
| NF-08 | 保守性 | VRM表示、LLM通信、整理計画、権限判断、実行を分離。LLM変更でファイル実行部を変更しない |
| NF-09 | データの扱い | 会話とファイル名を通常の診断ログへ出さない。会話保存を無効化できる。保存データは初期版ではOSアカウント権限で保護し、アプリ独自暗号化は未対応と表示 |

## 7. 初期版の完成判定

UC-01〜03が対象PCで通り、全必須要件を検証済みにする。最低限、VRM両世代、サーバー切断、整理中断、承認後のファイル変更、クラッシュ復旧、復元競合を含む。ファイル整理の保全条件を満たせない段階では「整理案のみ」の試用版とし、v0.1完成とはしない。

実装開始前の設計段階は終了しているが、全必須要件の完了を本書では宣言しない。特に2時間耐久、実機の操作環境差、性能値は個別の証跡をもって判定する。合格・不合格・検証中・未実施を区別した現状は[検証記録](verification.md)に記載する。

アバターの受け入れ条件は、ユーザー提供の対応VRMを読み込み、切替・表示・会話・整理を利用できることとする。外見や主観的な魅力は合否に用いない。異なる作者・外見の検証モデル、表情不足のモデルでも特定モデル名や表情名への依存がないことを確認する。口調はモデルの外見から固定せず、ユーザーの人格設定として扱う。

## 8. 将来の拡張方針

音声会話は利用者の指定によりMVPの対象外とする。将来追加する場合は、読み上げを先行し、次に押して話す方式の音声入力を追加する。常時待ち受けは別段階とする。長期記憶は利用者が内容を見て編集・削除できる方式にする。自律実行は、対象・操作・件数を限定した定型ルールから追加し、初期版の一括承認方式と区別する。
