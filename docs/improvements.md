# 改善記録

## 2026-09-20: v0.0.0.3 アーキテクチャ改善

設定競合、状態通知と永続化の結合、大量履歴時の全状態再送、Main内の重い保守処理を改善しました。会話／整理依頼の入口は明示選択、履歴は自動削除しない方針です。変更内容・測定・残る制約は [v0.0.0.3リリースノート](release-v0.0.0.3.md) と [検証記録](verification.md) に記載します。

## モーション・LLM選択・負荷改善（v0.0.0.2）

2026-09-19の追加要望に対応した実装。改良版を検証後、ユーザー指定のv0.0.0.2 Betaとして公開する。

## 変更

- 正規化Humanoidボーンで呼吸・揺れ・視線、手振り・うなずき・おじぎ・伸びを生成。おだやか／にぎやか／オフを選べる。アバター画面・右クリックからの手動再生にも対応する。姿勢変更と表情を補間し、異なる体格のVRMで任意のボーンが欠けても継続する。
- ドラッグ開始から終了までクリック透過を解除し、移動をまとめて透明ウィンドウの再描画を要求する。125% DPIで実際に観測したsetPosition反復時の寸法増加には、固定DIP寸法を含むsetBoundsを使用する。
- GGUFフォルダーとllama-server.exeを設定画面で指定し、会話上部の一覧からLLMを切り替える。フォルダー直下のみ検索し、分割GGUFは完全な組を1件として表示する。
- 管理モードでは1モデルずつ起動する。切替前に旧子プロセスの終了を待ち、起動中の停止、失敗表示、手動解放、既定5分の自動解放、送信時の再読込、アプリ終了時の停止に対応する。
- 外部起動のサーバーも引き続き利用できる。外部プロセスを停止・再設定しない。モデルと実行環境の自動ダウンロードはない。
- 非表示時は描画だけでなくアニメーション予約も取り消す。既定の描画品質はDPR上限1。当たり判定は約30Hz、判定の変化時のみIPCを送る。

## リソース設定

管理モードではcontext 4096、並列1、batch 512 / ubatch 128、promptキャッシュRAM 0を既定とする。GPU割当はllama.cppのfitに任せ、fit-targetは1024MiB、flash attentionはautoを指定する。KVキャッシュの型やモデル重みの量子化は変更しない。これらの起動引数は導入済みb10964の`--help`と[llama-server公式資料](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)で確認した。

GPUやRAMの必要量はモデルとコンテキストに依存する。小さいモデルへの切替と未使用時の解放で抑えられるが、9Bモデルを同じ品質のまま極端に小さくするものではない。外部起動スクリプトのcontext 16384などの設定は、そのまま維持する。

## 検証

Windows 11 Pro / RTX 5070 Laptop 8GB、Windows表示倍率125%、llama.cpp b10964 CUDA 13.3で実施。

- 単体・結合試験102件中101成功、1件は既存の8.3短名未対応環境によるskip。型検査成功。
- LFM2.5-1.2B-JPとQwen3.5-9Bを会話UIから切り替え、日本語本文を取得。会話履歴を保持して切り替えるため、後続モデルは以前のモデルの発言も履歴として受け取る。
- 公式検証VRMで全4動作を表示。押下を維持したドラッグの途中で複数回キャプチャし、透明でないモデル画素と描画の進行を確認。CDPのポインターdown/move/upでも離す前の表示を確認し、寸法は475×675物理pxを維持。
- 非表示2.5秒間のrequestAnimationFrameコールバック0、WebGL描画0。
- 既存の外部サーバー経路、SSE停止、途中応答、保存・復旧、モデル表示選択・非表示の再起動保持の回帰試験が成功。
